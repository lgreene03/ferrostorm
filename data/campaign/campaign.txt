# Ferrostorm campaign manifest v2:
#   mission file | player faction | title | allowed structure ids | allowed unit ids
# The allow columns gate the client build sidebar per mission (classic
# campaign tech progression). "-" means nothing buildable; absent columns
# mean everything (skirmish rules). Since ADR-009 the allow-list is an
# INTERSECTION with the tech tree rather than a rival to it: the tree says
# what is possible in the game, these columns say what this mission lets you
# have, and a mission may legitimately allow fewer things.
# Structure ids per World.GetStructureType: 1 power, 2 factory, 3 refinery,
# 4 construction yard (MCV-deployed, never queued), 5 turret, 6 superweapon,
# 7 veil, 8 depot, 9 wall, 11 barracks, 12 radar uplink, 13 outpost
# (map-placed, never built), 14 bridge (likewise), 15 emplacement,
# 16 airfield, 17 bastion, 18 shroud nest. (10 is ADR-005's reserved gate and
# still has no definition.)
# Unit ids per the catalogue: 1 cannon, 2 rifle, 3 rocket, 4 harvester,
# 5 raider, 6 scout, 7 mcv, 8 howitzer, 9 phantom, 10 bulwark, 11 engineer,
# 12 vanguard, 13 repair vehicle, 14 carrier, 15 strike flyer, 16 flak track,
# 17 infiltrator.
# STRUCT type 11 is the barracks and UNIT type 11 is the engineer. They are
# different namespaces and there is no clash, but the two columns below sit
# side by side, so read the header for the column you are in.
#
# This header had gone stale by six structure types and six units, which is
# the failure mode a list of magic numbers in a comment always has. It is
# corrected rather than removed because the columns below are unreadable
# without it; the permanent fix is for the loader to accept ids by NAME, and
# that is a ticket rather than a rider on this one.
